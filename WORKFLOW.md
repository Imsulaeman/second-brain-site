# WORKFLOW.md

How Claude, CODEX (OpenAI), and the user collaborate on this project.

---

## Roles

| Role | Who | Responsibility |
|---|---|---|
| **Plan Maker** | Claude (Anthropic) | Diagnose, architect, write specs, keep TASK.md updated |
| **Implementer** | CODEX (OpenAI) | Execute tasks from TASK.md, write code, verify in dev |
| **Content & Art** | User (Ilham) | Generate images via DALL-E, add content, make product decisions |

**Source of truth for this project:** `CODEX_PLAN.md` — the original master plan. TASK.md tracks execution status against it.

---

## Process

1. **Claude** reads `CODEX_PLAN.md` + codebase, identifies what's done and what's missing, writes actionable tasks in `TASK.md`
2. **CODEX** picks up a task marked `[ ] CODEX`, implements it, verifies in `npm run dev`, marks done
3. **User** handles tasks marked `[ ] USER` — image generation, content decisions, browser testing
4. **CODEX** logs what was done in `LOG/REPORT.md` with format `## YYYY-MM-DD — CODEX`
5. **Claude** reviews the log, updates the plan, adds next tasks

---

## Blocking Rule

**A task cannot start if its dependencies aren't met.**  
CODEX_PLAN.md lists images as a pre-condition for visual implementation.  
Images were not generated → CODEX should have used only CSS fallbacks and flagged the block.  
Going forward: if a task depends on assets the user must create, CODEX marks it `[ ] BLOCKED` and logs why.

## Content hygiene — mojibake check

When you paste content into `content/` from **any external source** (Google Docs, Word, web pages, PDF), run this check afterward:

```bash
grep -r "â€" content/
```

If there is any output, re-run the mojibake repair task from TASK.md. The affected characters are em dashes, curly quotes, ellipses, and arrows. Pasting directly from Obsidian or plain text editors is fine — the issue only occurs with rich text sources.

## Rules for CODEX

- Use `npm run dev` to verify — do NOT run `npm run build` (pre-existing OOM crash)
- Run `npx tsc --noEmit` before marking a task done
- Every task in TASK.md has a spec — follow it exactly
- If a task is unclear or has unresolved dependencies → mark `[ ] BLOCKED`, explain in log, don't guess
- Log every session in `LOG/REPORT.md`

## Rules for Claude

- Write specs with enough precision that CODEX can implement with zero ambiguity
- Include: root cause, files to change, exact code pattern, what to verify
- Reference `CODEX_PLAN.md` step numbers when relevant
- Keep TASK.md honest — don't mark things done if they haven't been browser-verified
